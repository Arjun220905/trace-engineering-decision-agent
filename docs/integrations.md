# Connect your tools

Open **Integrations** in the sidebar. Setup happens in the app; editing JSON or restarting the server is not required.

## Linear

1. Click **Connect Linear** and paste a personal API key with access to your workspace and issue creation.
2. Click **Load teams & members** and choose the destination team.
3. Optionally match transcript speakers to Linear members. Choose **Assign later** to create issues without an assignee.
4. Save the connection.

Trace checks read access again when saving. Publishing uses a mapped assignee when available. Otherwise it creates the issue unassigned and preserves the meeting owner in its description. After creation, choose **Open & assign** to assign or mention someone in Linear. A missing or different explicitly requested assignee holds the delivery for reconciliation. This reference supports discovery of up to 100 workspace users and teams. Larger workspaces need paginated discovery before using this setup flow.

### Follow the same issue across meetings

Trace matches later status statements to issues it previously published to the connected Linear team. Use the same Trace project and a clear task name, or say the Linear issue ID aloud. For example, “I’m working on the cursor parameter for the audit log endpoint” proposes **In progress**, and “ENG-314 is done” proposes **Done**. Trace keeps the timestamp and the existing issue link on the draft. Approve it, then publish to Linear to apply the change. A repeated commitment can link to the existing issue without changing its status.

Trace chooses the first workflow state in the requested category from the connected team. For a new issue, Linear chooses its team's default state, normally Backlog or Triage. Ambiguous matches stay out of tracker publishing. Trace checks the latest 500 prior deliveries in the connected team. If you imported a meeting before the original issue was published, open it and choose **Check Linear history** to refresh its drafts.

If a status request times out, open **Activity → Check Linear status** to verify the existing issue before retrying. Follow-up publishing changes the status field. The evidence stays in Trace.

## GitHub

1. Click **Connect GitHub**.
2. Paste a fine-grained token with Issues write permission for the repository, and enter `owner/repository`.
3. Load assignable members, optionally match speaker names to GitHub accounts, and save.

Setup checks repository and account read access. It does not prove issue-write permission until publishing. Up to 500 assignable users can be discovered. Unmapped owners create unassigned issues. **Open & assign** opens the issue for later assignment or a comment. When an assignee was requested, the creation response must contain it; an unexpected result is held for reconciliation.

## Jira Cloud

Enter the HTTPS Atlassian site, your Atlassian email, an API token, and the project key. The issue type defaults to **Task**. Saving checks project read access. Publish an approved action to create an issue with the transcript evidence and meeting owner. Use Jira to assign the issue afterward. Projects that require extra fields may reject issue creation.

## Trello

Enter a Trello API key, a token with read and write access, and the destination list ID. The list ID is the `id` in the board’s JSON export. Saving checks list read access. Publish an approved action to create a card with the meeting owner, evidence links, and any explicit due date. Use Trello to assign members afterward.

If Jira or Trello does not confirm creation, check the destination for the delivery marker shown in the issue or card description. Trace holds the delivery for manual reconciliation.

## Slack

Create an incoming webhook for the intended channel in your Slack app. Paste the HTTPS `hooks.slack.com/services/…` URL and save. The webhook itself selects the channel.

Saving validates the URL format and stores it; it does not send a test message. The status says **Configured**, rather than claiming verified delivery. The first reviewed meeting summary confirms delivery. Text is escaped before adding Slack markup, and evidence links are generated by Trace. Incoming webhooks do not return a message permalink, so none is invented.

## Notion

Share a parent page with a Notion integration. Paste the integration key and parent page link or ID in Trace. Saving checks read access to the page. Publishing creates one child ADR page per accepted discussion. The complete ADR Markdown is stored as bounded text blocks rather than claiming native Markdown-to-Notion formatting.

## MeetStream and Claude

Paste the provider key in the matching connection form and save. These connections are checked during the first import or extraction; the UI labels them **Configured**.

In **Import meeting → Send bot / MeetStream**, paste a Google Meet, Zoom, or Teams invite and select **Send bot to meeting**. Admit **Trace Notetaker** if it waits in the lobby. Trace keeps each bot under **Workspace bots**, even after you close the dialog or sign in from another browser. Use the **Stop bot** button on its row to ask it to leave. When Trace finds a usable transcript, choose **Use transcript** and create drafts. Imported rows link to their meeting. Workspace settings records who sent a bot or requested a stop. Enter an existing bot ID and select **Track existing bot** to bring an earlier bot into the list. You can also import directly using a bot ID or a transcript ID.

A bot ID lets Trace check the original recording. Trace reads supported 16-bit PCM WAV audio as a stream, with a limit of two hours and 768 MiB. It uses recording activity and the speaker timeline to correct clearly early turns and remove unsupported trailing thanks. When provider timestamps identify a sentence boundary, Trace can link a draft to that sentence. If an available recording does not support the sentence timestamp, Trace keeps the turn-level evidence. Imports from a transcript ID alone use provider timestamps.

Reviewers can click a timestamp to play the linked MeetStream recording. Use a bot ID when importing to attach the recording, or reimport an older bot-backed meeting by ID to link its existing transcript. Playback is available while MeetStream retains the audio.

Claude defaults to `claude-sonnet-5-5`; its model can be changed in the form. The response must pass the runtime evidence and owner checks. Model approval flags are reset to false. Without an AI key, rules extract explicit agreements and first-person commitments. They do not infer implicit consensus or deadlines.

## Storage and credentials

Integration keys and webhook URLs are encrypted with AES-GCM in the local D1 database. The random `APP_SESSION_SECRET` in `app/.env` derives the encryption key. **Keep this secret stable and back it up with the database.** Changing `APP_PASSWORD` does not change the encryption key.

Saved secrets are never returned by the settings API or persisted in browser storage. When managing an existing connection, leave the key blank to keep it. **Disconnect** removes the saved credential and prevents an environment fallback from silently reconnecting it.

Existing `.env` integration variables remain supported as optional fallbacks. In-app settings take precedence. See [.env.example](../.env.example) for their names. Environment connections are labelled as such and are not described as verified merely because values exist.

A connection only configures a destination. External writes still require approved outputs and an explicit Publish action. Selecting Linear and GitHub intentionally creates one issue in each; choose one tracker if you want one task overall.

## Verify a real meeting locally

1. Choose a real transcript and confirm its destination team, repository and Slack channel. Import it once; importing the same speaker turns again must return the existing meeting.
2. Compare every extracted discussion and action against its quoted source turn. Edit the ADR context, rationale and consequences, and check each action's owner and deadline before approval. Match those speakers to real provider accounts.
3. Open the ADR preview and each evidence link. Check the displayed timestamp, speaker and quote against the transcript. Evidence links open the source transcript turn. When a linked MeetStream recording is available, reviewers can play it from that timestamp.
4. Publish the reviewed meeting to the selected destinations. Read the actual Linear and GitHub issues to verify assignees, descriptions, evidence and the unique `trace:` marker. Read the Slack message in the intended channel and compare its approved discussions and actions.
5. Publish the unchanged meeting again. Every existing delivery should be skipped. Count the actual provider issues and Slack messages with the same markers: one per approved action per selected tracker, and one Slack summary. A `pending` or `uncertain` delivery requires checking the provider before reconciliation; never delete its claim just to retry.

With the app on localhost, evidence links work on this computer. Other recipients need access to the same running app to follow them. No deployment is required for the local acceptance test.
